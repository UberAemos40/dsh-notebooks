# Блокноты

Локальная библиотека заметок в Markdown для DeepSeek Harness.

## Что появляется в интерфейсе

- **Строка «Блокноты» в левой панели** — между «Задачи автоматизации» и «Ещё». Открывает страницу библиотеки в центральной колонке.
- **Страница библиотеки**: карточки заметок с превью и временем, поиск и счётчик; в меню карточки — закрепить сверху, открыть в панели справа, удалить. Новые заметки появляются из чата.
- **Заметка документом**: клик по карточке открывает заметку страницей — заголовок, оглавление «На этой странице», рендер Markdown, автосохранение. Второй путь (меню карточки) — открыть её вкладкой в правой панели рядом с чатом.
- **Иконка блокнота в шапке чата**: выделите текст в переписке и нажмите её — выделенное сохранится отдельной заметкой (во всплывающей подсказке — «В блокнот»). Без выделения кнопка неактивна (подсказка «Сначала выделите текст в чате»).
- **Иконка блокнота под ответом**: в строке действий рядом с копированием/лайком, сохраняет ответ целиком.

## Как наполнять из чата

Попросите в чате обычными словами:

- «Сделай конспект и сохрани в блокнотах»
- «Сохрани это в заметки»
- «Запиши в блокнот итоги обсуждения»

Агент сам пишет конспект и вызывает инструмент `notebook_save` с заголовком и Markdown-текстом; путь выбирать не нужно. Дополнительно доступны `notebook_list` (что уже есть в библиотеке) и `notebook_read` (прочитать заметку целиком).

Есть и слэш-команда: **`/notebook save`** — она отправляет агенту задание собрать конспект по текущей переписке, выкинуть служебный шум (пути, идентификаторы, вывод инструментов, служебные рассуждения, повторы) и сохранить только суть через `notebook_save`. Можно передать свой материал: `/notebook save <текст>`.

## Где лежат файлы

По умолчанию — `%USERPROFILE%\.dsh\notebooks` (`~/.dsh/notebooks`), одна общая папка для всех чатов и воркспейсов. Каждая заметка — обычный `.md` файл с коротким заголовком в начале (`title`, `created`, `updated`), поэтому библиотеку можно открыть любым редактором и скопировать на другую машину.

В шапке библиотеки есть кнопка **«Папка»**: она показывает текущий путь, открывает системный диалог выбора папки и переносит существующие заметки в новое место (галочка «Перенести существующие заметки»). Выбор запоминается в `%USERPROFILE%\.dsh\notebooks.json` и переживает перезапуск; кнопка «Вернуть папку по умолчанию» сбрасывает его.

Папку можно задать и в строке плагина в `cordis.patch.yml` (она используется, пока пользователь не выбрал свою):

```yaml
- id: notebooks
  name: dsh-notebooks
  config:
    directory: 'D:\Notes'
```

## Как устроен рендер

Текст заметки рендерит **markdown-it** (MIT): GFM-таблицы, зачёркивание, автоссылки, ограждения кода с меткой языка; сырой HTML в заметке отключён, поэтому вставленный в текст тег не выполнится. Библиотека лежит в `vendor/markdown-it.umd.min.js`, исходник интерфейса — `src/client.js`, собранный модуль `client.entry.js` получается командой `node build.mjs`. Блоки кода подсвечивает вендоренный **highlight.js** (BSD-3-Clause, ядро + набор языков: C#, JS/TS, JSON, Python, SQL, C/C++, bash, XML, CSS, Markdown, YAML, diff, INI, PowerShell). Язык берётся из метки блока, а при её отсутствии — угадывается по содержимому. Сборка языков лежит в `vendor/highlight.bundle.js` (генерируется скриптом `tools/make-highlight-bundle.mjs` из установленного пакета), лицензия — `vendor/LICENSE.highlight.js`.

## Ограничения

- Заметки хранятся на этом компьютере: синхронизации между устройствами нет.
- Кнопка в шапке сохраняет именно текущее выделение: если ничего не выделено, она открывает библиотеку.
- Удаление необратимо и не использует корзину.
- Путь к папке задаётся конфигом строки плагина; отдельного экрана настроек нет.
